# HeT FoodAI — coding assistant rules (2026-10-15)

## Non-negotiable
- Three owners: model/training (lead); dataset/QA (杨熙珂); inference/UI/deployment (孙璞月).
- Respect module boundaries. Coordinate modifications to shared `configs/`, `src/foodai/contracts.py`, `README.md` and `requirements` before edits.
- Do not claim data is downloaded, models trained, or tests passed without actual logs.
- Never invent samples or accuracy numbers; synthetic samples are only for smoke tests and must be labeled synthetic.
- `configs/classes.draft.json` is only a proposal. Formal training is forbidden until frozen `configs/classes.json` exists.
- Split at original image / capture group / source session level BEFORE augmentation; no source group or image SHA may cross any data split. Never train or tune on the frozen test set.
- Record dataset origin, license and any redistribution limits. Do not commit downloaded raw photos or proprietary enterprise media.
- Do not alter CR5AF or the personal homepage repository.
- Do not install system-wide Python/CUDA or overwrite existing environments. Use the project `.venv`.
- No fake prediction in the demo: show "model not ready" until a real checkpoint exists.
- No cloud services, credentials, user accounts, databases or hardware control unless explicitly approved.

## Interfaces
- Classes: `configs/classes.json` contains a frozen ordered list of 0-based `id`, `key`, `zh`.
- Dataset manifest: `docs/DATA_CONTRACT.md`.
- Predictor output: `docs/INFERENCE_CONTRACT.md`.
- Train code uses train + val only; the test split remains strictly held out.

## Verification
- Before each PR: run `python -m unittest discover -s tests -v`, show command, exit code and relevant sample output.
- Report exact files changed and limitations. Use branches `feat/data-*`, `feat/model-*`, `feat/app-*`.
- All code generated by AI must be explainable by the assigned student.
