# 独立实物验证的最小现场采集方案

2026-11-11。当前1,996张训练图没有完整可核验实物/会话身份，独立验证保持 **BLOCKED**。本方案尚未现场执行；不是已交付的验证集。

## 开始前

使用保留的 `tools/oven_training/recipes/physical-validation-intake.csv` 空白登记表。不要将文件序号、模型预测、不同角度或不同层位直接写成“新实物ID”。旧训练池保持整体train，不从中临时抽帧充当独立验证，也不根据本次A/B分数挑照片。

核实新实物来自新的采购/制作/交接记录，并且不是旧训练实物。采集者现场赋予真实持久ID，记录上游来源或批次；原料切片/切段的共同母体也要关联：同一土豆切块、同一玉米切段、同一鱼肉来源的多条，均不能拆成独立集合。身份无法核实时保留unknown和BLOCKED。

现有资格门禁还要求训练登记具备核实身份/会话字段。补采本身不会自动消除旧训练池的证据缺口；如旧登记无法补证，应由数据负责人给出可复核来源隔离证据，再协调实验侧资格规则。不要为了让程序通过而填入猜测的ID或人工签字。

## 最小试采规模

推荐起步为每类 **3个上游独立实物，共36个**，尽量来自至少两个采购/制作批次。先人工确定集合：每类2个用于开发验证、1个单独封存备用最终测试，拍摄会话也分开。来自同一母体或高度相关来源批次的对象需共同分组，不能只按件数宣称独立。

每个实物先冷态拍 **6张**：3个实际层位 × 锡纸/非锡纸两种背景，每格1张清晰图。这样共216张起步图片，其中24个验证实物最多144张、12个封存实物最多72张；这些只是计划数量，必须以现场实际登记为准。同一实物全部角度/层位/会话关联图始终留在同一集合。先不做连拍；额外角度可以补充，但不增加独立实物数。

这是最小功能与覆盖试采，**每类2个验证实物、1个封存实物不足以支持宽泛的泛化结论**。图片张数不能替代独立实物数、来源批次数；后续需继续增加独立来源。封存图不用于选择BN策略、Epoch、ROI、分辨率或阈值。

## 十二类及重点覆盖

类别ID保持0–11：asparagus、bacon、broccoli、chicken_wing、croissant、french_fries、potato、salmon、toast、corn、sausage、steak，不新增或重排。

| 重点类别 | 现场应记录/覆盖 | 不能据此推断 |
| --- | --- | --- |
| potato | 不同真实块茎；皮色/外形/大小、原料与生熟状态 | 同一块土豆换方向等于另一实物 |
| sausage | 淡色及其他外观；实际配料/品牌/来源批次 | 浅色圆柱必然是哪种肉，或模型判鸡翅就应改标签 |
| salmon | 实际原料来源、共同母体、不同切形与可见纹理 | 同一鱼肉条的多个切片是独立来源 |
| corn | 白/乳白和黄色外观均需真实样本，记录已知品种/状态 | 文件名代表品种，或同一穗切段是不同实物 |

其余八类同样登记、采集、报告样本数；不能只收集或展示有改善的类别。类别语义、生熟/加工范围有变化时先由团队确认，不在采集中悄悄修改。

## 需要本人完成的最少操作

1. **摆出实物并登记来源、真实ID和预定集合。** 应看到一个实物对应一个持久ID，照片数量与实物数量分开；来源不明就标BLOCKED。
2. **冷态连接现有采集软件、确认画面，再拍6格。** 应看到完整食材、清晰纹理、无严重欠曝/反光遮挡；背景、实际层位、相机/烤箱标识、会话、照明均按事实填写。软件自动控制加热不在本方案内。
3. **核对原图可读、尺寸、SHA及标签。** 用人工原料记录确认主食材，不能用模型Top-1当真值；损坏、混合主食材、遮挡严重图单独隔离，不覆盖原图。
4. **核对分组和签字后运行资格预检。** 必须无跨集合实物/会话/组/字节或像素重复、无重复图凑类别覆盖；记录审核者和时间。仍不合格则保持BLOCKED，禁止将train回看当val。
